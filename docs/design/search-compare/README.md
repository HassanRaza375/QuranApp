# Search: prototype and revamp compared (Phase 10)

Generated by `scripts/screenshots/phase-10-search.mjs` on the production build. The revamp's answers are the **real recorded responses** in `tests/fixtures/alquran-search-*.json` (no network). The prototype shows its own sample content, so the pairs compare layout and behaviour, not words.

- Sixteen pair images: `start|results|jump|offline-desktop|mobile-light|dark.jpg` (prototype left, revamp right; "mobile" is 375 px).
- Revamp-only states, at desktop light and mobile (375) dark: `state-<name>-<device>-<theme>.jpg` (`filters-open`, `filters-on`, `arabic`, `urdu`, `no-results`, `failed`, `scope-people`, `short`).
- The 390 px phone (an iPhone 14), light and dark: `state-<name>-m390-<theme>.jpg` (`start`, `results`, `arabic`, `urdu`, `offline`, `filters-open`, `people`).

## Review on 2026-10-22 (390 px, dark, offline, mixed Arabic and English)

Looked at one by one: 390 px dark results, Urdu (dark and light), Arabic (light), offline (dark), people (light), the 375 px dark Filters sheet, and the desktop light results pair. The other images were generated and not individually reviewed.

**Found and fixed (images regenerated after):**

| What was off | Fix |
| --- | --- |
| The offline note had a visible gap in its text: the 44 px "Try again" button sat inside the paragraph and stretched one line | Try again is on its own line under the text (offline and error) |
| On a phone the Arabic name beside Surahs, People and Stories results was hidden (as in the prototype), so mixed Arabic and English showed no Arabic | The Arabic name shows on every width, on the right (at most 45% of the row, wrapping rather than truncating), highlighted when it is what matched |
| Urdu results were heavy: about 7 lines per ayah at the default Urdu size | 17 px in results (about 4 to 5 lines); the Urdu face elsewhere is unchanged |
| The match highlight was faint in light mode | A stronger tint of the accent (24%), in both themes |

**Checked and fine:** the six chips wrap to two lines at 390 px with 44 px targets; the Filters button count; the strip; English reference lines over right-to-left Arabic and Urdu (the header stays left-aligned, the text right-aligned); dark mode contrast on results, notices and the sheet.

## Differences from the prototype (deliberate)

| Prototype | Revamp | Why |
| --- | --- | --- |
| Groups for Duas, Knowledge base and Daily Fiqh | Ayahs, Surahs, People, Stories, Notes only | Those pages do not exist until Phases 12 and 13; a result must not open "not rebuilt yet". Each later phase adds its group (`DECISIONS.md`) |
| No filters | One **Filters** button: edition (10), surah, juz, saved ayahs only | The legacy page had them; approved |
| Chips appear only for groups that have results | The six chips are always there, with counts once something is typed | "The type chips stay visible" (approved) |
| Sample ayahs labelled "Saheeh International" | Real results; the Ayahs group names the edition searched ("English: Pickthall", "Urdu: Jalandhry", "Arabic: Quran text", "Tafsir: Muyassar") and each row carries the edition's short name | The reader's English is not an edition the search service has, so no name may be shown for text that is not that translation |
| Recent searches stored as `{id, q, at}` objects, 12 at most | A list of strings, 15 at most, in the legacy key | The legacy app calls `.toLowerCase()` on each entry, so objects would break it after a rollback |
| History saved after 1.5 s idle | Saved only after a search that found something; at once on Enter or when a result is opened | Approved: never save a failed or empty search |
| Searches from 2 characters in every group | Device groups from 1 character, the ayah search from 2 after about 300 ms | Approved |
| "Show all N" shows up to 60 | Up to 60 shown, with "Showing the first 60 of N" | Simpler, and the same cap as the legacy page |
| The strip is labelled Al-Fatihah, Juz 15, An-Nas | First and last surah names only (the real spellings) | The middle label was not at the middle |
| The lede names duas, fiqh topics and an Arabic example | "Ayahs, surahs, people, stories and your notes. Marks and spelling variants are ignored." | Only what exists; no typed Arabic |
| A "/" hint inside the box | No hint; the `/` key still works from any page | Kept the box plain; can be added if you want it |
| Notes results link nowhere | A note opens the item it is on | The prototype had no target |
| The "Offline preview" button | Real offline detection, and "Try again" | Prototype-only control |
| Matching also folds teh marbuta to heh | Folded in the device groups and in highlighting only; the app's own normaliser (Surah listing, Library) and the upstream's ayah search are unchanged | Decided 2026-10-22: one letter for Search, two for the other filters |
| The box is focused on load, also on a phone | Focused on desktop only | A phone keyboard would cover the page |

## Not a difference but worth knowing

- A text search the upstream answers with 404 ("nothing found") shows one "Failed to load resource" line in the browser console. Chromium logs every 404 fetch and a page cannot silence it; the legacy page did the same.
