# The player: prototype and revamp compared (Phase 4B)

Generated by `scripts/screenshots/phase-04b-player.mjs` on the production build. **No real audio is played**: the audio element is a stand-in (as in the browser tests), so the images show the real interface in each state. Real playback, the lock screen and the large generic-type files are device checks.

- Four pair images: `desktop|mobile-light|dark-player.jpg` (prototype overlay left, revamp sheet right).
- Eleven states, each at desktop light and mobile dark: `state-<name>-<device>-<theme>.jpg` (mini-playing, mini-paused-restored, mini-loading, mini-error, mini-buffering, sheet-playing, sheet-resume-line, sheet-first-surah-prev-disabled, sheet-custom-speed, sheet-error, sheet-reciter-note).

Looked at by me: the desktop light pair, the sheet's resume line at mobile dark and the mini player's error at mobile dark. The others were generated and not individually inspected.

## Differences from the prototype (deliberate)

| Prototype | Revamp | Why |
| --- | --- | --- |
| "Now playing" with a surah and ayah ("Al-Fatihah · ayah 2") and a 6:35 scrubber | The surah, "Recited by <reciter>", a real slider with the file's own length | Whole-surah player; per-ayah audio is 4C |
| Previous / Next arrows | Previous and Next surah, plus Back 10 s and Forward 10 s; both ends are real buttons with `aria-disabled` | Approved decisions 3 and 5 |
| Speed chips, reciter short names | Speed chips (and a custom chip for a Settings value outside them); the five full reciter names, with "Switching reciter restarts this surah." shown first | Decision 4 |
| Two switches (Repeat, next surah) | The same two switches, bound to the legacy keys | Same settings as Settings |
| "Save audio to device" as a normal button | Visible but disabled with "Saving audio arrives with Downloads" | Decision 3; Phase 11 |
| Mini player: text and a bar | Title button that opens the sheet, a status line (Paused at 12:34, Buffering…, errors), a progress line, Try again, Play/Pause | States and recovery |
| (no resume) | "Resume where you stopped · Al-Kahf · 12:34" in the sheet, and the mini player paused after a reload | New behaviour; nothing automatic |

## Things you may notice

- At 375px the mini player's error text is cut off ("Couldn’t play. Audio needs a conne…"); the full message is in the sheet, in the listing row and in the screen-reader status. Say if you would rather it wrap onto two lines (the bar would grow).
- For a restored item the length is not known yet, so the sheet shows 0:00 as the length and a disabled slider until the file has loaded.
