# Page: Tasbeeh

- Routes (legacy, kept): `/tasbeeh` and `/tasbeeh/[id]`
- Phase: 9B
- Prototype section: `d-page-tasbeeh` / `m-page-tasbeeh`
- Offline level: A. The dhikr are bundled and counts are on the device.
- Indexable: no (`robots: noindex`, as the legacy pages).

## Purpose

Count a dhikr, with a goal, and keep the totals on this device.

## Layout

- `/tasbeeh`: one `h1` "Tasbeeh" and six counters (SubhanAllah, Alhamdulillah, Allahu Akbar, La ilaha illallah, Astaghfirullah, Custom Dhikr) as links, each with its Arabic, transliteration, meaning and "count / goal".
- `/tasbeeh/[id]`: "‹ All dhikr", the Arabic (if any), the `h1` (the dhikr's transliteration), the meaning, then:
  - the **count button**: a 240px circle that is a real `button` (`aria-label` "Count. 12 of 33"), with a progress ring (decoration) and the count and goal inside; "Tap the circle, or press Space or Enter, to count."
  - **Goal** chips 33 / 99 / 100 (`aria-pressed`, 44px);
  - **Cycles completed** and **Lifetime count**;
  - **Reset count** (disabled while the count is 0);
  - **Vibrate on count**, a switch, shown only where the browser can vibrate.

## Data

The dhikr (id, Arabic, transliteration, meaning) are the legacy presets, generated by `scripts/gen-tasbeeh-presets.mjs` from the legacy `useTasbeeh.ts` into `app/data/tasbeehPresets.generated.ts`. **There is no "After prayer" or Tasbih of Fatima** (the legacy app has none; the prototype's were typed by us). A counter whose id is not a preset opens as a counter named by its id (as the legacy page does); `name-<n>` shows the name's own Arabic, transliteration and meaning and links back to the name.

## Behaviour (all as the legacy counter unless stated)

- **Count:** count and lifetime go up by one; reaching the goal adds a cycle and starts again from 0. Space and Enter count; a key held down counts once (auto-repeat is ignored).
- **Announcement:** a polite status line says "12 of 33" after each count, "Goal of 33 reached. 3 cycles completed." at a cycle, "Count reset to 0." on reset.
- **Reset:** the count returns to 0, cycles and lifetime stay, with a toast and **Undo** (the legacy page used a confirm dialog).
- **Goal:** choosing a different goal sets the count back to 0 (the legacy behaviour), now with **Undo** that restores both.
- **Vibration:** 15 ms for a count and 120/60/120/60/120 ms for a finished cycle, as the legacy page. On by default where supported, a switch next to the counter turns it off (kept in `quran:tasbeeh-prefs:v1` = `{ vibrate }`, additive), and it is **never** used while Reduce motion is on in Settings (the switch says so). The ring does not animate while Reduce motion is on.
- **Viewing writes nothing:** a counter is written to storage on its first count, reset or goal change (the legacy page created entries while rendering).

## Storage

`quran:tasbeeh:v1`, exactly the legacy shape: `{ [id]: { count, target, cycles, lifetime } }`. Other counters, unknown fields in an entry and unknown fields at the top are kept through every operation. `tests/tasbeeh.test.ts` loads the **legacy composable itself** and runs it beside the revamp's code on the same legacy-shaped data, step by step, and the stored records are equal; it also checks that the legacy code accepts the revamp's `name-<n>` counters and leaves them intact. A malformed stored value is shown as the legacy default instead of "NaN".

## States

| State | What shows |
| --- | --- |
| Never counted | 0 of 33, nothing stored |
| Mid-count | The count, the ring part-filled |
| Goal reached | Count 0, cycles + 1, the announcement, the longer vibration |
| Vibration not supported | The switch is not shown |
| Reduce motion on | No vibration and no animation; the switch is off with a note |
